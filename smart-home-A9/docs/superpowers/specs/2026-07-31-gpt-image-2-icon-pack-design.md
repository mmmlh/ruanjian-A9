# 智能家居 gpt-image-2 专属图标包设计

## 1. 目标

使用用户提供的 OpenAI 兼容图片生成服务和 `gpt-image-2` 模型，为智能家居项目生成一套风格统一的专属 PNG 素材包。

本次仅生成和整理图片素材，不修改 ArkTS 页面、OpenHarmony 资源引用、现有 SVG、后端接口或运行逻辑。

## 2. 已确认范围

### 2.1 最终主图

交付 9 个无文字图标：

| 文件标识 | 中文名称 | 核心视觉语义 |
| --- | --- | --- |
| `app_home_beacon` | 应用图标 | 房屋轮廓与松绿色核心光点组成“归家信标” |
| `device_light` | 灯光 | 简洁灯泡或吸顶灯结构 |
| `device_ac` | 空调 | 壁挂式空调及出风口 |
| `device_door_lock` | 门锁 | 现代智能门锁面板 |
| `device_curtain` | 窗帘 | 对称窗帘与中央开合缝 |
| `device_humidifier` | 加湿器 | 桌面加湿器与克制雾气 |
| `device_temperature_sensor` | 温度传感器 | 圆形温度传感器与温度刻度语义 |
| `device_humidity_sensor` | 湿度传感器 | 圆形湿度传感器与水滴语义 |
| `device_pir_sensor` | 人体感应器 | 壁挂式 PIR 传感器与感应窗口 |

不生成智能插座、底部导航、页面操作、状态提示、场景插画或空状态插画。

### 2.2 生成数量

每个图标独立生成 A、B 两个候选，共 18 张成功候选图。每个图标从两个候选中选择一张作为最终母版。

不得在没有用户再次批准的情况下增加成功生成数量。网络、限流或服务端失败允许对同一请求做有限退避重试，但不应产生超过 18 张成功候选图。

## 3. 视觉系统

### 3.1 风格方向

采用“微立体双材质”方案：

- 哑光陶瓷白作为设备主体；
- 石墨黑作为结构、开口或外壳；
- 松绿色作为状态灯或关键感知语义；
- 光线固定从左上方照入；
- 视角固定为轻微正面俯视，不使用夸张透视；
- 阴影柔和、短促，不制造悬浮过高的效果；
- 主体居中，四周保留约 14% 安全区；
- 不包含文字、字母、数字、品牌、水印、人物、房间背景或多余配件。

### 3.2 色彩锚点

提示词统一锚定项目现有主题色：

- 石墨黑：`#16212D`
- 深石墨：`#213142`
- 松绿色：`#14875B`
- 浅绿色：`#E4F3EC`
- 陶瓷白：接近 `#FFFFFF`

图片生成模型不保证逐像素命中色值，因此色彩作为生成锚点和后续视觉筛选标准，不做可能破坏材质的强制全图换色。

### 3.3 背景规则

- `app_home_beacon` 使用完整不透明的石墨黑圆角方形背景；图形本身为陶瓷白房屋轮廓和松绿色核心光点，不出现 “A9” 或其他文字。
- 8 个设备图标使用透明背景，仅保留设备主体和贴近主体的柔和阴影。

若服务返回非透明设备背景，仅允许对从画布边缘连通的近似纯色背景做确定性清除。清除会损伤陶瓷白主体时，该候选应判定为不合格，不采用大范围颜色抠除。

## 4. 生成接口

### 4.1 请求

使用：

```text
POST https://chiyicn.com/v1/images/generations
```

请求体采用文档展示的 OpenAI 兼容字段：

```json
{
  "model": "gpt-image-2",
  "prompt": "Single isolated smart-home icon, soft dimensional dual-material style, matte ceramic white, graphite black and pine green, centered on a square canvas, no text or watermark.",
  "n": 1,
  "size": "1024x1024",
  "response_format": "b64_json"
}
```

API 密钥只通过当前进程内存传入 `Authorization: Bearer ...`，不得写入仓库文件、生成报告、提示词清单、命令脚本或日志。

### 4.2 提示词结构

每次请求由以下固定部分组成：

1. 单一图标的设备或品牌语义；
2. 微立体双材质、固定色彩、视角和光源；
3. 透明背景或应用图标圆角底要求；
4. 1:1 构图、14% 安全区和统一视觉重量；
5. 无文字、无水印、无品牌、无场景和无多余部件的负面约束。

两个候选使用相同语义和风格约束，不通过改变风格来制造差异。

## 5. 处理流程

数据流为：

```text
提示词清单
  -> 18 次独立成功生成
  -> Base64 解码为候选 PNG
  -> 候选联系表与逐图视觉检查
  -> 每类选择 A 或 B
  -> RGBA 与方形画布规范化
  -> 多尺寸高质量缩放
  -> 最终联系表、清单、报告和 ZIP 包
```

候选文件使用稳定命名：

```text
{asset_id}_a.png
{asset_id}_b.png
```

选定母版使用：

```text
{asset_id}.png
```

## 6. 候选选择标准

按以下顺序筛选：

1. 缩放到 64px 后能否立即识别设备类型；
2. 是否遵守陶瓷白、石墨黑和松绿色材质规范；
3. 是否没有文字、水印、重复部件、断裂结构或错误透视；
4. 与其余图标的视角、光源、留白和视觉重量是否一致；
5. 透明边缘和主体阴影是否干净；
6. 应用图标的“房屋 + 核心光点”语义是否在小尺寸下成立。

候选联系表可以包含文件名和选择标记，最终图标本身不得包含任何文字。

## 7. 异常处理

- `401` 或 `403`：立即停止，不重试，不记录密钥或完整认证头。
- `429` 或 `5xx`：使用有限次数的指数退避重试同一请求。
- 响应缺少 `data[0].b64_json`、Base64 非法或图片无法解码：记录该请求失败并重试同一候选。
- 图片尺寸、格式或透明度不符合要求：进入候选不合格记录，不擅自增加成功生成次数。
- 同一图标两个候选都不合格：停止最终打包并向用户报告该图标，不用不合格素材冒充完成品。

## 8. 输出结构

所有结果写入：

```text
output/generated-icons/
├── candidates/                 # 18 张原始候选图
├── masters/                    # 9 张选定的 1024px 母版
├── sizes/
│   ├── 512/                    # 9 张 512px PNG
│   ├── 256/                    # 9 张 256px PNG
│   ├── 128/                    # 9 张 128px PNG
│   └── 64/                     # 9 张 64px PNG
├── candidate-contact-sheet.png
├── final-contact-sheet.png
├── manifest.json
├── generation-report.md
└── smart-home-icon-pack.zip
```

`manifest.json` 记录：

- 文件标识和中文名称；
- 设备类型；
- 选中的候选 A 或 B；
- 输出尺寸、颜色模式和透明度要求；
- 每个输出文件的 SHA-256；
- 模型名与不含密钥的接口地址。

`generation-report.md` 记录请求结果、候选选择理由、异常和最终验收结论，不包含 API 密钥或完整认证信息。

ZIP 包包含 `masters/`、`sizes/`、最终联系表、清单和报告，不包含未选中的候选图。

## 9. 验收

### 9.1 自动检查

- 所有候选和最终文件均能解码为 PNG；
- 母版为 `1024x1024`；
- 导出尺寸精确为 `512x512`、`256x256`、`128x128` 和 `64x64`；
- 设备图标为 RGBA，四角透明；
- 应用图标背景完整不透明；
- 清单中的文件均存在，SHA-256 与实际文件一致；
- ZIP 能正常打开且只包含规定内容；
- 输出目录和生成报告不包含 API 密钥。

### 9.2 视觉检查

- 候选联系表用于比较每类 A/B 候选；
- 最终联系表同时展示 1024px 缩略图和 64px 实际尺寸预览；
- 9 枚最终图标无文字、水印、结构错误和明显风格漂移；
- 小尺寸下灯、空调、门锁、窗帘、加湿器及三类传感器之间不会混淆；
- 应用图标不出现 “A9”，并清楚表达“归家信标”。

## 10. 范围边界

本次不修改：

- `openharmony/entry/src/main/ets/**`
- `openharmony/entry/src/main/resources/base/media/**`
- `openharmony/AppScope/resources/base/media/**`
- 现有导航和操作 SVG
- 云端、模拟器和后端代码

最终交付是可供后续集成的独立 PNG 素材包。是否接入 OpenHarmony 应用由后续独立任务决定。
