# A9 智能家居两天 UI 收口设计

## 目标

在不改变 FastAPI、MQTT、WebSocket、路由和设备控制语义的前提下，用两天时间统一 OpenHarmony 客户端的 8 个页面：登录、注册、首页、设备、设备控制、自动化、数据监测和个人中心。

首要验收目标是视觉一致性和完成度：同一套颜色、字号、间距、圆角、图标、导航、反馈和触控尺寸贯穿全部页面。此次改造不新增业务能力，也不重写后端接口。

## 现状问题

- 根页面同时出现返回箭头和底部主导航，导航层级冲突。
- `DeviceManagePage.ets` 有 32 处页面内硬编码颜色，且编辑、删除、房间选择等触控区偏小。
- 首页、自动化和设备控制页保留了多套未使用的旧 Builder，增加视觉漂移和维护成本。
- 多个页面使用 Emoji 或生僻 Unicode 字符作为图标，风格和字形随系统变化。
- 卡片圆角集中在 22-30vp，页面大量使用卡片套卡片，信息层级过于松散。
- 自动化页出现“便于答辩演示”“更像完整产品”等开发阶段文案。
- 设备页默认展开扫描、候选设备、房间选择、改名和绑定流程，一级页面过载。
- 删除设备、删除规则和退出登录缺少统一的危险操作确认。
- 状态提示、错误提示、空状态和加载状态在不同页面分别实现。

## 设计方向

保留当前浅色、绿色强调的产品方向，但从“米家风大圆角卡片堆叠”收口为更安静的操作型界面。

### 设计令牌

- 页面背景：`#F4F6F5`；主表面：`#FFFFFF`；次级表面：`#EEF2F0`。
- 主文字：`#19211D`；次级文字：`#66716B`；弱文字：`#89938E`。
- 强调/成功：`#14875B`；柔和背景：`#E4F3EC`。
- 警告：`#A96917`；柔和背景：`#FFF0D5`。
- 危险：`#B34F4F`；柔和背景：`#F9E7E7`。
- 间距继续使用 4/8/12/16/24vp。
- 普通卡片和输入框圆角统一为 8vp；状态胶囊保留全圆角；大型状态区不超过 12vp。
- 正文不低于 14sp，辅助文字不低于 12sp，非关键时间戳最低 11sp。
- 所有可点击控件的有效触控尺寸不低于 44vp。

### 共享组件

扩展 `ControlCenterTheme.ets` 和 `ControlCenterKit.ets`，形成以下复用边界：

- `AppTopBar`：根页面标题和任务页返回标题使用同一骨架；根页面不显示返回按钮。
- `AppBottomNav`：首页、设备、自动化、我的固定四项，使用 `replaceUrl`，图标和文字同时显示。
- `StatusBanner`：信息、成功、警告、危险四种语义，颜色不作为唯一信息载体。
- `SectionTitle`：统一标题、辅助文字和可选尾部动作；无动作的尾部文本不可伪装成按钮。
- `EmptyState`：统一加载失败、无数据和下一步动作。
- `ConfirmPanel`：设备删除、规则删除和退出登录共用确认结构。
- `PrimaryButton`、`SecondaryButton`：统一高度、圆角、禁用状态和文字层级。

导航和操作图标使用随应用打包的 Lucide 风格 SVG 媒体资源，避免 Emoji、字体符号和不稳定的系统符号名称。

## 页面设计

### 登录与注册

- 共用中性背景、品牌标识、标题、表单和主按钮视觉。
- 移除大面积蓝色背景；绿色只用于主操作和成功状态。
- 输入框增加可见字段标签，错误统一通过 `StatusBanner` 展示。
- 注册页保持可滚动，键盘弹出和 320vp 窄屏下提交按钮仍可达。

### 首页

- 阅读顺序固定为：标题与同步时间、全屋状态、异常提醒、快捷场景、房间/常用设备、最近活动。
- 全屋状态区集中展示在线设备数、温度、湿度和场景数。
- 标题旁只保留一个明确的刷新动作；不再用搜索图标跳转设备页。
- “编辑”等不可点击的尾部文案移除或改为真实动作。

### 设备

- 作为一级根页面，不显示返回箭头。
- 默认只展示已绑定设备、房间筛选和“添加设备”入口。
- 扫描、候选设备、房间和名称编辑放入页面内二级添加流程，不与设备列表同时展开。
- 删除设备先进入确认状态；编辑和删除操作触控区至少 44vp。

### 设备控制

- 作为任务页保留返回按钮，不显示底部主导航。
- 共用设备状态、主操作、参数调节和结果反馈骨架。
- 保持现有“离线仍允许尝试下发”的业务策略，并用一致文案明确说明。
- 滑杆仍使用现有防抖，不改变 MQTT 指令语义。

### 自动化

- 作为一级根页面，不显示返回箭头。
- 顶部只保留一个新增入口，移除重复加号和开发/答辩文案。
- 规则摘要保持“当……时，执行……”结构；开关和删除操作分层。
- 删除规则先确认，操作结果使用统一反馈组件。

### 数据监测

- 作为任务页保留返回按钮。
- 实时、历史、日志使用统一分段控件。
- 保留现有时间范围、历史摘要和记录列表，不引入第三方图表库。
- 加载、空数据和错误状态使用共享组件。

### 个人中心

- 作为一级根页面，不显示返回箭头。
- 用紧凑账户信息区和设置列表替代大头像卡片堆叠。
- 合并两个等价的退出入口，只保留“退出登录”。
- 退出登录先确认；修改密码错误使用统一危险状态。

## 状态与错误处理

- 所有异步操作保留加载、成功、失败三个可见状态。
- 成功信息不把“指令已下发”误写为“设备状态已同步”。
- 错误文案使用中文可操作信息，不显示 `Unknown error`、原始 JSON 或 MQTT topic。
- 危险操作采用页面内确认面板，避免引入新的弹窗控制器和编译风险。

## 两天排期

### 第一天

1. 写 UI 源码回归测试并确认失败。
2. 修改主题令牌和共享组件。
3. 加入 SVG 图标资源。
4. 收口登录、注册、首页和设备页。

### 第二天

1. 收口设备控制、自动化、数据监测和个人中心。
2. 清理已触及页面中的旧 Builder、Emoji、硬编码颜色和开发文案。
3. 运行根目录 UI 回归、后端回归和 HAP 构建。
4. 在 320vp 等效窄屏和常规手机宽度检查文字、触控区、底部导航和键盘可达性。

## 验收标准

- 8 个页面均引用共享主题；根页面使用同一底部导航。
- 首页、设备、自动化和我的不显示返回箭头；任务页显示返回动作。
- 页面内不再出现 Emoji 设备/导航图标或开发阶段文案。
- 新触及的辅助文字不低于 12sp，操作控件不低于 44vp。
- 设备、规则和退出登录均有确认状态。
- 不修改后端 API、MQTT topic、设备命令参数和实时更新链路。
- 根目录测试、后端测试和 HAP 构建通过。

## 非目标

- 不重做信息架构或新增页面路由。
- 不引入第三方 ArkUI 组件库或图表库。
- 不改造后端数据库、鉴权、规则引擎或设备模拟器。
- 不为所有设备类型重画独立插画；只统一导航、操作和通用状态图标。
