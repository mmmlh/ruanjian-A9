# 后台模拟器可视化控制台设计

## 1. 目标

在 `cloud` 目录内新增一个面向联调和演示的模拟器可视化控制台。控制台通过现有 Nginx 以 `https://localhost/simulator/` 提供，展示 17 台 Python 模拟设备的在线状态、实时数据和 MQTT 事件，并允许操作现有协议支持的控制类设备。

本项目最重要的约束是冻结现有接口：不新增或修改 FastAPI 端点，不改变请求或响应字段，不改变 MQTT 主题与消息格式，不改动模拟器设备逻辑。

## 2. 已确认范围

### 2.1 包含

- 原生 HTML、CSS、JavaScript 单页控制台。
- 使用现有默认账号自动调用登录接口并获取 JWT。
- 展示全部 17 台模拟设备，按名称、房间、类型和在线状态筛选。
- 展示后端、数据库、MQTT 和实时 WebSocket 连接状态。
- 对灯、空调、门锁、窗帘和加湿器下发现有命令。
- 只读展示温度、湿度和人体感应传感器。
- 显示有界的实时 MQTT 事件流和既有操作日志。
- 桌面端运维工作台布局，并适配移动端单列布局。

### 2.2 不包含

- 修改、创建或删除设备、房间、场景和自动化规则。
- 启停 Docker 容器或单独启停某个模拟设备。
- 改写传感器生成参数、强制注入温湿度或人体感应值。
- 新增模拟器管理 API、MQTT WebSocket 监听器或后台页面路由。
- 修改 OpenHarmony 客户端。

## 3. 技术方案

采用原生静态页面，文件位于 `cloud/simulator-ui/`。现有 Nginx 新增 `/simulator/` 静态资源路径，`docker-compose.yml` 只增加只读目录挂载。原有 `/api/`、`/ws/`、`/docs`、`/openapi.json` 和根路径代理行为保持不变。

预期文件边界：

- `cloud/simulator-ui/index.html`：语义化页面结构和启动状态容器。
- `cloud/simulator-ui/styles.css`：工作台、控件、响应式和状态样式。
- `cloud/simulator-ui/app.js`：认证、API 客户端、状态管理、渲染和交互。
- `cloud/simulator-ui/vendor/`：本地托管的界面图标资源，避免运行时 CDN 依赖。
- `cloud/nginx/nginx.conf`：新增 `/simulator/` 静态资源位置。
- `cloud/docker-compose.yml`：将静态资源只读挂载到 Nginx 容器。

不引入 Node 构建链或新的运行时服务。

## 4. 接口冻结与白名单

控制台只能调用下列既有契约：

| 用途 | 方法与路径 | 使用方式 |
| --- | --- | --- |
| 就绪检查 | `GET /api/ready` | 获取数据库和 MQTT 健康状态 |
| 自动登录 | `POST /api/login` | 请求体使用既有 `username`、`password` 字段 |
| 设备状态 | `GET /api/states` | 首次加载及每 10 秒状态校准 |
| 设备命令 | `POST /api/devices/{id}/command` | 请求体使用既有 `action`、`params` 字段 |
| 操作日志 | `GET /api/data/logs?limit=100` | 初始化最近操作记录 |
| 实时事件 | `WS /ws/realtime?token={jwt}` | 接收既有 `{type, topic, payload}` 消息 |

所有受保护的 HTTP 请求使用 `Authorization: Bearer {jwt}`。控制台不依赖数据库结构，不直接连接 MQTT，也不解析或生成接口以外的内部协议。

## 5. 页面结构

### 5.1 顶部状态栏

顶部显示产品名、当前工作区，以及后端、MQTT 和实时流状态。状态必须区分“连接中”“正常”“异常”和“重连中”，不能仅依靠颜色表达。

### 5.2 设备概览和筛选

概览显示设备总数、在线数、房间数和近一分钟事件数。筛选区包含名称或 MQTT 主题搜索、房间筛选、设备类型筛选、在线状态筛选和刷新按钮。

设备表使用稳定行高，展示在线标记、名称、MQTT 主题、房间、当前状态和最后更新时间。点击一行只改变浏览器内的选中状态，不发起写操作。

### 5.3 类型化检查器

右侧检查器根据选中设备类型显示控件：

| 设备类型 | 控件和命令 |
| --- | --- |
| `light` | 开关；亮度 0-100；色温选项；发送 `on`、`off` 或 `set` |
| `ac` | 开关；温度 16-30；模式；风速；摆风；发送 `on`、`off` 或 `set` |
| `door_lock` | 上锁和解锁；解锁要求输入非空 `auth_code` |
| `curtain` | 开、关和位置 0-100；发送 `open`、`close` 或 `set` |
| `humidifier` | 开关；档位 1-3；目标湿度 30-80；发送 `on`、`off` 或 `set` |
| `temperature_sensor` | 只读显示数值、单位和最后更新时间 |
| `humidity_sensor` | 只读显示数值、单位和最后更新时间 |
| `pir_sensor` | 只读显示有人或无人及最后更新时间 |

可调参数先保存在本地草稿中，用户点击“发送命令”后才提交。发送期间禁用当前设备的重复提交。界面使用切换开关、分段控件、滑块、数值输入和图标按钮表达相应操作；图标按钮提供可见焦点和工具提示。

### 5.4 实时事件面板

底部固定事件面板显示时间、主题和 JSON 载荷，支持主题过滤、暂停自动滚动、恢复滚动和清空本地记录。事件只保留最近 300 条。清空只影响浏览器内存，不调用后台删除接口。

移动端将设备表压缩为可扫描列表，检查器移动到列表下方，事件面板成为可折叠区域，确保控件和文字不重叠。

## 6. 数据流与状态同步

1. 页面加载后请求 `/api/ready`，显示服务就绪状态。
2. 控制台以既有默认账号调用 `/api/login`，JWT 仅保存在内存中，不写入 URL 或持久化存储。
3. 登录成功后并行读取 `/api/states` 和 `/api/data/logs`。
4. 控制台建立带 Token 的 `/ws/realtime` 连接，将 MQTT 事件追加到本地事件队列。
5. 收到传感器、状态或响应主题时，更新对应设备的可见状态；每 10 秒重新获取 `/api/states`，消除丢包或重连期间的状态偏差。
6. 用户发送控制命令时，使用现有设备 ID 和命令契约提交。HTTP 成功响应更新当前设备，后续 WebSocket 事件用于确认模拟器实际响应。

UI 状态与服务状态分离：筛选条件、选中设备、参数草稿和事件暂停状态属于浏览器；设备状态、在线状态和操作结果始终以现有后端响应为准。

## 7. 异常处理

- 就绪检查失败：展示阻断状态和重试入口，不伪造设备在线状态。
- 自动登录失败：停止后续受保护请求，显示登录失败阶段和重试按钮；界面和控制台日志不得输出密码。
- `401`：清除内存 Token，自动重新登录一次并重放一次原请求；再次失败后停止循环重试。
- 命令提交失败：保留当前参数草稿，恢复提交按钮并显示 HTTP 状态和后台 `detail`；不得将失败命令显示为成功状态。
- 命令已下发但后续持久化失败：对既有 `command_post_dispatch_failed` 显示“可能已执行，请观察实时状态”的不确定状态。
- WebSocket 断线：按 1、2、5、10、30 秒上限递增重连；重连期间定时状态拉取继续工作。
- 非法或未知消息：保留在原始事件流中，但不用于覆盖设备状态。

## 8. 自动登录安全边界

自动登录是已确认的本地演示需求。默认凭据会随静态资源发送到浏览器，因此该入口不适合暴露到不受信任网络。实现需在代码注释和页面错误状态中明确本地演示定位，不在 UI 文本、事件日志或异常对象中回显密码。此限制不通过新增认证接口规避，以遵守接口冻结要求。

## 9. 视觉与可用性

整体采用安静、密集、工作导向的运维界面。主色使用中性灰和深炭色，青绿色表示正常操作，琥珀色表示等待或警告，红色只用于错误。页面不使用装饰性渐变、悬浮大卡片或营销式标题。

键盘用户可以依次访问筛选项、设备行和控制器。所有图标按钮包含 `aria-label` 和 `title`，状态同时使用文字与颜色，焦点样式清晰。交互控件维持稳定尺寸，避免状态变化造成布局跳动。

## 10. 测试与验收

### 10.1 自动检查

- 运行现有后端测试，确认 API 和 MQTT 行为未回归。
- 运行 `docker compose config`，确认静态挂载和 Nginx 配置有效。
- 增加针对静态入口、接口白名单和关键设备命令映射的聚焦测试。
- 检查前端源码不存在新 API 路径、直接 MQTT 连接或数据库访问。

### 10.2 浏览器验收

- `https://localhost/simulator/` 可直接打开并自动登录。
- 17 台设备均可展示，搜索和所有筛选组合有效。
- 五类控制设备可发送合法命令并收到可见反馈。
- 三类传感器只读，无误导性的写入控件。
- WebSocket 事件实时追加，暂停、筛选、清空和 300 条上限有效。
- 后端未启动、认证失败、命令失败和 WebSocket 断线均有明确状态与恢复路径。
- 桌面和移动视口无控件重叠、文字溢出或横向不可控滚动。
- 浏览器控制台无未处理异常，关键网络请求只命中接口白名单。

## 11. 完成标准

当控制台可通过现有 Docker Compose 在 `/simulator/` 访问，完成上述设备展示、控制、实时事件和异常恢复，并且所有现有接口契约与模拟器代码保持不变、自动与浏览器验收通过时，本功能完成。
