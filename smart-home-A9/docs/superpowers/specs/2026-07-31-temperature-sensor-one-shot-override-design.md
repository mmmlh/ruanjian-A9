# 温度传感器一次性读数覆盖设计

## 1. 目标

在现有后台模拟器可视化控制台中，为三台温度传感器增加一次性读数写入能力。用户可以输入 `15-38°C` 范围内的值，例如 `28°C`；后台立即显示该值，温度模拟器在约 20 秒内持续上报该值，随后恢复原有正态分布随机读数。

本功能必须保持接口冻结：不新增或修改 FastAPI 路径、HTTP 方法、请求字段、响应字段、MQTT 主题或通用命令信封格式。

## 2. 范围

### 2.1 包含

- 客厅、卧室和书房三台 `temperature_sensor` 的一次性读数写入。
- 控制台提供 `15-38°C` 滑块、数字输入和明确的提交命令。
- 复用现有 `POST /api/states/{entity_id}` 状态写入端点。
- 复用现有 `home/{room}/temperature_sensor/command` MQTT 主题。
- 模拟器收到合法写入后立即上报指定温度，并在 20 秒覆盖窗口内继续上报该温度。
- 覆盖过期后，在下一次既有 5 秒采样周期恢复随机温度。
- 新的合法写入会替换当前临时值，并从新命令到达时重新计算 20 秒窗口。

### 2.2 不包含

- 修改空调设定温度的既有行为。
- 为湿度或人体感应传感器增加写入能力。
- 持久化临时覆盖；模拟器重启后立即恢复自动生成。
- 增加暂停、永久固定或自定义持续时间。
- 修改现有状态写入端点对直接 API 调用的数值校验契约。

## 3. 冻结接口

浏览器继续使用现有端点：

```http
POST /api/states/temperature_sensor.device_1
Authorization: Bearer {jwt}
Content-Type: application/json

{"attributes":{"value":28}}
```

卧室和书房分别使用既有实体 `temperature_sensor.device_7` 和 `temperature_sensor.device_12`。响应仍是现有 Home Assistant 风格状态对象。

后台使用设备当前 `mqtt_topic` 拼接既有 `/command` 后缀，发布通用命令信封：

```json
{"action":"set","value":28}
```

不增加 `duration`、`ttl` 或其他字段。20 秒持续时间是温度模拟器内部固定行为。

## 4. 数据流

1. 用户选择温度传感器，在控制台输入 `15-38°C` 的有限数值。
2. 控制台调用现有状态写入端点，请求体只包含既有 `attributes.value`。
3. 后台沿用现有数据库更新、状态投影刷新和响应构造逻辑。
4. 对范围内的温度传感器值，后台额外通过该设备既有 `/command` 主题发布 `set` 命令。
5. 温度模拟器校验命令后保存内存临时值和单调时钟截止时间，并立即发布一次传感器数据。
6. 截止时间之前，既有 5 秒采样循环继续发布临时值。
7. 截止时间到达后，下一次采样清除覆盖并恢复原有 `random.gauss(25.0, 0.5)` 生成逻辑。
8. 既有 MQTT 状态同步和 WebSocket 广播把即时值及恢复后的随机值传回控制台。

## 5. 模拟器并发与时间语义

MQTT 回调线程写入临时覆盖，采样线程读取覆盖。温度模拟器使用互斥锁保护临时值和截止时间，避免命令与采样并发时读取不一致。

截止时间使用单调时钟，防止系统时间调整改变 20 秒窗口。窗口从合法命令被模拟器接收时开始。由于自动采样周期为 5 秒，随机读数预计在命令后 20-25 秒之间重新出现；这是“约 20 秒”的验收范围。

## 6. 控制台交互

温度传感器检查器保留当前读数展示，并增加：

- `15-38°C`、步长 `0.1°C` 的滑块。
- 与滑块同步的数字输入框。
- “写入一次”提交按钮。

只有用户提交后才发起状态写入。提交期间禁用重复提交；成功后使用状态写入响应刷新设备行和检查器，实时 MQTT 消息负责后续确认与自动恢复。湿度和人体感应检查器继续显示“只读传感器”。

## 7. 校验与错误处理

- 控制台拒绝非有限数值及 `15-38°C` 以外的输入，不发请求。
- 模拟器只接受 `action == "set"`、有限数值且位于 `15-38°C` 的命令；其他命令不改变当前覆盖。
- 后台状态写入的原有请求与响应模型保持不变。
- MQTT 发布失败时使用现有 HTTP 错误机制返回失败，不伪装为完整成功；已经提交的状态仍遵循现有端点的提交语义。
- UI 保留输入草稿并显示后台 `detail` 或通用失败信息。

## 8. 测试与验收

### 8.1 自动测试

- API 客户端测试：状态写入使用现有路径和精确请求体。
- 设备模型测试：温度写入接受 `15`、`28`、`38`，拒绝越界值和非有限值。
- 后台测试：温度状态写入仍返回原响应结构，并向现有命令主题发布精确命令；其他设备状态写入不触发该命令。
- 模拟器测试：合法命令立即生效、20 秒内保持、过期后恢复随机生成、重复命令重置窗口、非法命令不改变状态。
- 静态契约测试：没有新增 API 路径、MQTT 主题或请求字段。
- 完整后端回归和 Docker Compose 配置检查。

### 8.2 浏览器验收

- 三台温度传感器均显示一次性写入控件。
- 写入 `28°C` 后，列表和检查器立即显示 `28°C`。
- 20 秒覆盖窗口内的实时传感器事件保持 `28°C`。
- 20-25 秒后出现新的自动随机温度并更新界面。
- 湿度和人体感应仍无写入控件。
- 桌面和移动端控件无溢出或重叠，浏览器控制台无错误。

## 9. 完成标准

当用户能通过现有状态接口在控制台对任意温度传感器执行一次性写入，指定值在模拟器中保持约 20 秒后自动恢复，同时全部接口路径、HTTP 字段、MQTT 主题与通用命令格式保持不变，并通过自动与浏览器验收时，本功能完成。
