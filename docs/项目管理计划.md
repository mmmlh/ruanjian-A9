# A9 赛题项目管理计划

## Context

- 团队：1-2人，OpenHarmony/ArkTS 零基础
- 目标：第十五届软件杯 A9 "基于OpenHarmony操作系统的家居设备控制系统"
- 截止：2026年6月30日 15:00（距今约8周）
- 约束：人力非常有限，需做最务实的范围管理

## 核心策略

**MVP优先 + 仿真先行 + 文档驱动**：
1. 先用纯仿真跑通全流程（APP + MQTT通信 + 模拟设备）
2. 四大功能模块全部覆盖，拿满60分基础分
3. 后期如有余力再加硬件实物（非必需但加分）
4. 安全性做"可演示"级别（TLS+AES）
5. 文档和PPT从第一周就开始积累，不堆到最后

---

## 一、团队分工（1-2人模式）

### 方案A：2人团队（推荐）

| 角色 | 职责 | 技术栈 |
|------|------|--------|
| **成员A：APP开发 + 文档** | ArkTS前端、UI界面、设备管理页面、PPT+设计文档 | DevEco Studio、ArkTS、ArkUI |
| **成员B：后端/网关 + 硬件** | MQTT Broker搭建、设备模拟器、加密、硬件对接 | Node.js、MQTT、传感器 |

### 方案B：1人独立完成

按以下优先级顺序推进，每个阶段做完再做下一个：
1. APP UI（最简单上手）
2. 模拟设备 + MQTT 通信
3. 安全机制
4. 文档+视频

---

## 二、开发方法论

采用**周迭代 + 里程碑驱动**：
- 每周末做一次集成测试，确保当周产出可运行
- 每两周出一个"可演示版本"
- 第6周冻结功能，最后2周只做文档和视频

## 八、达成竞赛目标的关键

综合考虑 1-2 人零基础的现实条件，务实的目标是：

| 目标 | 策略 |
|------|------|
| **保底：省二/省三** | 四个模块全做但深度一般，仿真方案，基础安全机制 |
| **冲刺：省一/国三** | 四个模块做深 + 三重加密可演示 + 服务卡片 + 1个鸿蒙亮点 |
| **极限：国二+** | 以上 + 实物硬件 + 真实传感器数据 + 跨设备协同 |

建议以"保底省二、冲刺国三"为实际目标，不做超出能力的过度设计。
