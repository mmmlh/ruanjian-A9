## Slide 3: 项目背景与痛点分析

**智能家居的三大痛点**：

| 痛点 | 现状 | 影响 |
|------|------|------|
| 🔴 生态碎片化 | 各品牌独立 APP，用户需安装多个应用 | 体验割裂 |
| 🔴 数据安全隐患 | 家庭隐私数据明文传输，云端泄露风险 | 隐私威胁 |
| 🔴 标准不统一 | 缺乏统一操作系统底座，跨品牌联动困难 | 扩展受限 |

**我们的解决方案**：
- ✅ 基于 OpenHarmony 统一操作系统底座
- ✅ 一个 APP 控制全屋设备
- ✅ 三层加密安全体系
- ✅ MQTT 标准 IoT 协议

## Slide 6: 核心技术方案 — 三层安全体系（亮点一）

**从传输到数据的全方位保护**：

```
第一层：传输加密
  ┌──────────────────────────────┐
  │  MQTT over TLS + HTTPS       │
  │  防止中间人窃听               │
  └──────────────────────────────┘
            ↓
第二层：身份认证
  ┌──────────────────────────────┐
  │  JWT Token (HS256)           │
  │  24小时过期 + 动态签名        │
  │  Token 内含 AES 密钥          │
  └──────────────────────────────┘
            ↓
第三层：数据加密
  ┌──────────────────────────────┐
  │  AES-256-CBC                 │
  │  随机密钥 + 随机 IV + PKCS7  │
  │  门禁/空调等关键数据加密传输   │
  └──────────────────────────────┘
```

**效果**：即使截获网络包，也无法解密设备控制指令

## Slide 7: 核心技术方案 — 多品牌空调适配（亮点二）

**统一指令模型 + 品牌翻译器**：

```
        APP 统一指令
    {"power":"on","mode":"cool","temp":24}
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
  格力       海尔       美的
PWR_ON    POWER=1       1
MODE_COOL MODE=COOLING  2
TEMP_24   SET_TEMP=24   24
```

**支持品牌**：格力 | 海尔 | 美的 | 通用（可扩展）

**优势**：
- APP 无需感知品牌差异
- 新增品牌只需添加翻译表
- 后端自动识别并转换指令

## Slide 8: 核心技术方案 — 智能联动引擎（亮点三）

**发布/订阅 + 规则引擎**：

```
PIR传感器         规则引擎            灯光设备
  │                  │                  │
  ├─ presence=true ─→│                  │
  │                  ├─ 评估"人来开灯"   │
  │                  ├─ 条件满足！       │
  │                  │                  │
  │                  ├─ 发送 on 指令 ──→│
  │                  │                  ├─ 开灯
  │                  │                  ├─ 亮度 80%
  │                  │←── 状态上报 ────┤
  │                  │                  │
```

**预置规则**：
| 规则 | 触发条件 | 动作 |
|------|----------|------|
| 人来开灯 | PIR 有人 + 灯关 | 开灯(80%) |
| 人走关灯 | PIR 无人 + 灯开 | 关灯 |
| 高温制冷 | 温度 > 28°C + AC关 | 开AC(制冷26°C) |
| 高湿除湿 | 湿度 > 80% + AC关 | 开AC(除湿) |

## Slide 9: 产品演示要点

**功能演示流程**（~4分钟）：

1. **登录注册**（30秒）
   - 演示登录界面和认证流程

2. **控制中心**（60秒）
   - 仪表盘总览 + 房间切换 + 设备状态
   - WebSocket 实时推送温湿度数据

3. **照明控制**（45秒）
   - 开关灯 + 亮度滑块 + 色温切换
   - 人来开灯自动联动

4. **空调控制**（45秒）
   - 温度调节 + 模式切换 + 风速
   - 品牌标签 + 高温自动制冷

5. **智能门禁**（30秒）
   - 远程开锁 + 安全加密提示
   - 自动上锁

6. **数据加密演示**（30秒）
   - 抓包对比：明文 vs 密文

## Slide 10: 创新点总结

| 序号 | 创新点 | 描述 |
|------|--------|------|
| 1 | **OpenHarmony 原生** | 基于 Stage 模型开发，利用 ArkTS 声明式 UI |
| 2 | **三层安全体系** | TLS + JWT(嵌入AES密钥) + AES-256-CBC |
| 3 | **多品牌空调适配** | 统一指令模型 + 可扩展品牌翻译器 |
| 4 | **可扩展规则引擎** | JSON 配置 + 热加载 + 条件组合 |
| 5 | **仿真先行策略** | 11个设备模拟器，无需硬件即可全链路演示 |
| 6 | **Docker 容器化** | 4个容器一键部署，适合快速交付 |
| 7 | **WebSocket 实时推送** | 传感器数据毫秒级更新 |
| 8 | **MQTT 标准协议** | 低带宽、低功耗，IoT 行业标准 |

## 附录：PPT 制作建议

1. **配色方案**：深蓝色主题 (#1A3C6E + #2B579A)，白色/浅灰背景
2. **字体**：中文用微软雅黑，英文用 Segoe UI
3. **图标**：使用 Emoji 或专业的 IoT/智能家居图标
4. **动画**：淡入淡出，避免过度动画
5. **图表**：架构图建议用 draw.io 或 Visio 绘制
6. **时长**：控制在 7 分钟内（含 4 分钟演示 + 3 分钟介绍）
